# UX 리디자인 설계 — captures 시안 반영

- 작성일: 2026-07-17
- 근거 시안: `captures/` 15장 (로그인 플로우 5장, 온보딩 7장, 홈 1장, 클럽 목록+필터 2장)
- 진행 구조: Phase 0(공통 기반) → 1(클럽) → 2(홈) → 3(계정) → 4(온보딩), Phase별 독립 브랜치+PR

## 1. 개요

`captures/` 폴더의 디자인 시안을 기준으로 로그인/계정 플로우, 온보딩 위저드, 홈, 클럽 목록+필터 4개 영역의 UX를 재구성한다. 시안 레이아웃/구성요소를 그대로 재현하되 기존 CVA/Radix 컴포넌트 시스템과 브랜드 토큰(orange-500)으로 구현하고, 백엔드(마이그레이션·API·스토리지)까지 완성한다.

## 2. 범위 / 비범위

**범위:**
- 클럽 목록 카드 리디자인 + 필터 바텀시트 + 서버 필터링 API
- 홈 재구성: 내 다음 모임 히어로, 인라인 검색바, 운세·건강 2열 카드, 인기 모임(모임 단위), 추천 콘텐츠·커뮤니티 인기글 실데이터화
- 로그인 랜딩/이메일 로그인 분리, 회원가입 약관 동의+이름/휴대폰 수집, 아이디 찾기, 비밀번호 재설정
- 온보딩 시안형 UI(진행 바, 드롭다운 지역, 대분류→세부 취미, 사진 등록 단계 신설)
- 상기를 위한 DB 마이그레이션, 스토리지 버킷, 공통 컴포넌트 추출

**비범위 (후속 과제):**
- 바텀내비 "일정" 탭 (현행 "정보" 탭 유지 — 사용자 결정)
- 반경(km) 필터 (좌표 컬럼만 선반영, 필터 UI/쿼리는 제외 — 사용자 결정)
- 알림 페이지 (홈 시안의 종 아이콘은 대상 페이지가 없어 이번엔 미노출)
- 채팅/일정/마이 등 시안에 없는 화면

| 결정 | 내용 | 근거 |

| 진행 순서 | 기반→클럽→홈→계정→온보딩 | W1 런치 루프(클럽 중심)와 정렬, 마이그레이션 선행 |

## 4. Phase 0 — 공통 기반

### 4.1 DB 마이그레이션 (`supabase/migrations/*.sql`, drizzle-kit 금지)

단일 마이그레이션 파일로 통합. Drizzle 스키마 파일은 SQL과 동기화만 한다.

**h_clubs 컬럼 추가:**
- `sido text`, `sigungu text` — 지역 필터용. 백필: 기존 `region` 값이 시/도 명과 일치하면 `sido` 설정
- `lat text`, `lng text` — 반경 필터 후속 대비 선반영 (h_club_meetings의 text 타입 관례 유지)
- `activity_days text[] not null default '{}'` — 활동 요일 (`mon`~`sun`)
- `meeting_type h_meeting_type` — 신규 enum (`regular`(정기)/`flash`(번개)/`social`(친목)/`study`(스터디)), null 허용(미지정)
- `age_range h_age_range not null default 'all'` — 신규 enum (`all`/`50s`/`60s`/`70plus`)
- 인덱스: `(sido, sigungu)`, `(category)`
- 기존 `region` text는 하위 호환 위해 유지, 신규 저장 시 `"{sido} {sigungu}"`로 동기 기록

**h_profiles 컬럼 추가:**
- `name text` — 실명 (아이디 찾기용)
- `phone text` — 휴대폰, 숫자만 정규화 저장 (`01012345678`), 인덱스 추가 (unique 아님 — 가족 공유 가능성)

**h_user_consents 테이블 신설:**
- `id text pk default gen_random_uuid()::text`, `user_id text not null references h_profiles(id) on delete cascade`, `consent_type text not null` (`terms`/`privacy`), `version text not null`, `agreed_at timestamp default now()`
- FK 성립 조건: 회원가입 서버 라우트가 프로필 스텁을 먼저 생성 (5.3 참조)

**h_auth_attempts 테이블 신설 (rate limit용):**
- `id text pk`, `ip text not null`, `action text not null` (`find_id` 등), `created_at timestamp default now()`, 인덱스 `(ip, action, created_at)`

**h_hobbies 카테고리 재편:**
- 기존 4개 카테고리(운동/문화/생활/교육)를 시안 6개 대분류로 재매핑: `운동/스포츠`, `예술/공예`, `요리/맛집`, `음악/악기`, `여행/아웃도어`, `독서/자기계발`
- hobby id는 불변 (h_user_hobbies 보존), category 값만 update. 재배치 규칙: 기존 세부 취미 명칭 기준 최근접 대분류로 이동 (예: 등산·골프·수영·요가·배드민턴·탁구·걷기→운동/스포츠, 미술·서예·사진→예술/공예, 요리→요리/맛집, 악기연주·음악감상→음악/악기, 여행·낚시·원예→여행/아웃도어, 독서·외국어·컴퓨터·역사탐방→독서/자기계발). 전체 행 매핑표는 구현 플랜에 명시

### 4.2 스토리지

- Supabase Storage 버킷 `h-avatars` 확인 후 없으면 생성 (공유 Supabase이므로 `h-` 접두사)
- 정책: public read / authenticated write (본인 `{userId}/` prefix만) / 5MB 제한, image mime만

### 4.3 공통 컴포넌트 추출 (`src/components/club/`)

- `ClubCard` — 썸네일(coverImage, 없으면 카테고리 이모지 배경 fallback), "인기" 배지(memberCount 20명 이상), 제목, 1줄 설명, 지역·멤버수·카테고리 태그, `AvatarStack`. 홈/클럽 목록의 중복 마크업 대체
- `AvatarStack` — 멤버 아바타 최대 3개 + `+n` 카운트
- `SearchBar` — 인라인 검색 입력 + 필터 버튼 슬롯 (홈/클럽 공용)
- 클럽 목록 쿼리: lateral join으로 클럽별 최근 활성 멤버 3명의 `avatarUrl` + 잔여 수 포함

## 5. Phase 1 — 클럽 목록+필터 (club-all/club-list 시안)

### 5.1 목록 화면 (`/club`)

- 헤더: "클럽" 타이틀 + 우상단 "클럽 만들기", 서브카피, `SearchBar`+필터 버튼(적용 개수 뱃지), 칩 탭 5개 유지
- 탭 동작 재정의: 전체(기본) / 근처(내 프로필 sido·sigungu 프리셋 필터 — 현행 위치권한 EmptyState 대체) / 취미별(카테고리 섹션이 열린 필터 시트 오픈 — 현행 무동작 수정) / 인기(memberCount 정렬) / 내 클럽(가입 클럽)
- 적용된 필터 칩: 검색바 아래 최대 3개 + 개별 X 제거 + "초기화" (시안 TIP 규칙)
- 카드: `ClubCard` 사용

### 5.2 필터 바텀시트

Radix Dialog 기반 바텀시트. 섹션 순서(시안 그대로, 반경 제외):
1. 지역 — 시/도, 시/군/구 Select 2개 (행정구역 정적 JSON, 시/도 선택 시 시/군/구 연동)
2. 카테고리 — 멀티 칩 (전체 + h_hobbies 6개 대분류 + 기타)
3. 활동 요일 — 월~일 멀티 칩
4. 모임 유형 — 전체/정기 모임/번개 모임/친목 위주/스터디·학습
5. 연령대 — 전체/50대/60대/70대 이상
6. 멤버 수 — 전체/5명 이하/6~15명/16~30명/30명+
7. 하단 "적용하기 (n)" 고정 버튼, 우상단 "초기화"

### 5.3 서버 필터링 API

- `GET /api/clubs` — Zod 쿼리 검증 + `api-response` 패턴 (프로젝트 표준 API 패턴 준수)
- 파라미터: `q`(이름/설명/카테고리 ilike), `sido`, `sigungu`, `categories`(csv), `days`(csv, `activity_days &&` 배열 overlap), `meetingType`, `ageRange`, `members`(`lte5`/`6-15`/`16-30`/`gte30`), `sort`(`recent` 기본/`popular`), `scope`(`all` 기본/`mine`)
- 속성 미지정 클럽은 해당 필터 활성 시 제외 (단, `age_range='all'` 클럽은 연령대 필터에 항상 포함)
- 페이지는 서버 컴포넌트 초기 로드 + React Query로 필터 변경 시 재조회

### 5.4 클럽 생성/수정 폼 확장

- 신규 수집: 시/도·시/군/구(Select), 활동 요일(멀티 칩), 모임 유형, 연령대
- 대표 장소(카카오맵 선택 → lat/lng)는 선택 입력
- `region`은 `"{sido} {sigungu}"`로 동기 기록

## 6. Phase 2 — 홈 (home 시안)

위→아래 구성:
1. **헤더**: 로고 + 프로필 아바타(→ `/mypage`). 시안의 알림 종은 알림 페이지 부재로 이번엔 미노출 (편차 §10)
2. **검색바**: 인라인 `SearchBar` + 필터 버튼, 탭/클릭 시 `/search` 이동 (홈 내 인라인 검색 아님)
3. **내 다음 모임 히어로**: 내가 참여(`h_meeting_participants.status='joined'`) 중인 미래 모임 임박순 최대 3개 캐러셀. D-day 뱃지, 제목, 일시(`5/25(토) 09:30` 형식), 장소, 클럽 coverImage 배경, "모임 자세히 보기" 버튼, 페이지 인디케이터. **없으면** 클럽 둘러보기 CTA 카드로 대체
4. **오늘의 운세·건강 한 줄** 2열 카드: 운세는 기존 `generateFortune` 재사용(요약 1줄+"자세히 보기"→`/fortune`), 건강 한 줄은 `h_info_contents` `category='health'` 최신 1건의 `summaryBox`(없으면 정적 문구 로테이션, "자세히 보기"→해당 글)
5. **신규 유저 위젯** (기존 OnboardingCarousel/KakaoShare/NotificationOptIn): 시안에 없지만 W1 런치 장치이므로 히어로 아래 위치로 유지
6. **추천 콘텐츠**: mock 제거 → `h_info_contents` 최신/인기 3건 (카테고리 뱃지, 제목, 조회수·좋아요), "더보기"→`/info`
7. **인기 모임**: 시안대로 **모임 단위** 가로 스크롤 — 다가오는 `h_club_meetings` 참여자순 5건 (D-day 뱃지, 이미지, 제목, 일시, 장소, 참여자 `AvatarStack`, `n/max명`), "더보기"→`/club`
8. **커뮤니티 인기글**: mock 제거 → `h_community_posts` 최근 7일 `likeCount + commentCount×2` 상위 3건 (제목, 작성자 닉네임, 상대시간, 좋아요·댓글 수), "더보기"→`/community`
- 기존 "프로필 완성" 배너는 검색바 아래·히어로 위, "나를 위한 추천"(개인화 클럽)은 인기 모임 아래에 유지

## 7. Phase 3 — 로그인/계정 플로우

### 7.1 라우트 구성

| 라우트 | 시안 | 내용 |
|---|---|---|
| `/login` | login1 | 히어로 이미지 + "다시 만나서 반가워요" + 카카오 노랑 버튼 + "이메일로 로그인"(→`/login/email`) + 회원가입 링크. 현행 동일 페이지 토글 제거 |
| `/login/email` | login2 | 이메일/비밀번호 + 로그인 상태 유지 체크 + "비밀번호 찾기" 링크 + 하단 "아이디 찾기 \| 회원가입" + 브랜드 카드 |
| `/register` | login3 | 이름, 휴대폰(형식 자동 하이픈, 본인확인 용도 고지), 이메일, 비밀번호(8자+), 비밀번호 확인, 약관 동의 블록. 닉네임 필드는 온보딩과 중복이므로 제거(시안과 일치) |
| `/find-id` | 아이디 찾기 | 이름+휴대폰 → 마스킹 이메일 결과 (`ab***@d***.com`) + "로그인하러 가기" |
| `/find-password` | 비밀번호 찾기 | 이메일 입력 → 재설정 링크 발송. 시안 레이아웃(보안 안내 카드) 유지, 문구는 "재설정 링크 발송"으로, 이름 필드는 링크 방식에서 불필요해 제거 |
| `/reset-password` | (신규) | 재설정 링크 착지. recovery 세션으로 `updateUser({password})`. 토큰 없으면 안내+재발송 링크 |
| `/terms`, `/privacy` | (신규) | 약관/개인정보 처리방침 본문 페이지. 표준 초안 삽입, 운영 검토 필요 명시 |

**proxy 허용목록**: `src/proxy.ts`가 비-/api 페이지 인증을 강제하므로 위 신규 공개 라우트 전부를 공개 허용목록에 추가.

### 7.2 회원가입 처리 (`POST /api/auth/signup` 신설)

1. Zod 검증: 이름(한글 2~10자), 휴대폰(정규화 후 010 시작 10~11자리), 이메일, 비밀번호(8자+), 필수 약관 2종 동의 여부
2. 서버 Supabase 클라이언트 `signUp` (name/phone은 user_metadata에도 기록)
3. 성공 시 Drizzle로 `h_profiles` 스텁 upsert (`id`, `nickname`=이름 임시값 — 온보딩에서 교체, `name`, `phone`)
4. `h_user_consents` 2건 insert (terms/privacy, version은 문서 버전 상수)
5. 실패 시 단계별 롤백 불필요 (스텁/동의는 재시도 시 upsert)
- 카카오 가입자: 약관 동의는 카카오 OAuth 동의 화면으로 갈음 (본 플로우 미적용, 정책 문서화)

### 7.3 아이디 찾기 (`POST /api/auth/find-id` 신설)

1. rate limit: `h_auth_attempts` 기준 IP당 10분 내 5회 초과 시 429
2. `h_profiles`에서 `name` + 정규화 `phone` 일치 조회
3. 일치 시 service role `auth.admin.getUserById(id)`로 이메일 획득 → 마스킹 반환. 카카오 프로바이더 계정이면 "카카오로 가입된 계정입니다" 안내
4. 불일치 시 어느 필드가 틀렸는지 노출하지 않는 단일 메시지 (계정 열거 방지)
- 한계(문서화): 이 릴리스 이전 가입자는 name/phone이 없어 조회 불가 → 안내 문구에 고객 문의 경로 포함

### 7.4 로그인 상태 유지

- 체크(기본): 현행 장기 쿠키 유지
- 해제: 브라우저 클라이언트 cookieOptions를 세션 쿠키로 — 브라우저 종료 시 만료. 구체 메커니즘은 구현 플랜에서 `@supabase/ssr` 옵션으로 확정

## 8. Phase 4 — 온보딩 위저드

### 8.1 공통 프레임

- 헤더: 뒤로가기 + 단계명 + 우상단 "문의하기"(mailto, 주소는 `NEXT_PUBLIC_SUPPORT_EMAIL`, 미설정 시 미노출) + 헤더 하단 얇은 주황 진행 바 (현행 번호 원형 StepIndicator 교체)
- 단계: ① 글자 선택 → ② 닉네임 → ③ 지역 → ④ 취미(대분류→세부) → ⑤ 사진
- 기존 sessionStorage 진행 저장/복원, "건너뛰기" 유지

### 8.2 단계별

1. **글자 선택**: 시안 2×2 카드("보통 크기/조금 크게/아주 크게/가장 크게" + "안녕하세요" 미리보기). 기존 4단계 스케일(sm/md/lg/xl)에 라벨만 시안 문구로 매핑, 기본값(lg) 유지. 음성 가이드 체크박스는 시안에 없지만 기존 기능이므로 유지
2. **닉네임**: 단일 입력, 실시간 유효성 — 2~7자 한글/영문/숫자 (시안 placeholder 준수), 위반 시 빨간 보더+"닉네임 형식이 올바르지 않습니다". 중복 검사는 하지 않음(현행 스키마에 unique 없음, 변경 없음). 기존 추천 닉네임 그리드는 시안대로 제거
3. **지역**: 시/도·시/군/구 Select 2개 (5.2와 동일한 행정구역 정적 JSON 공유). 현행 버튼 그리드+자유입력 대체
4. **취미**: 1단 — 대분류 6카드 그리드(아이콘+라벨, 단일 선택) → 2단 — 해당 대분류의 세부 취미 칩 그리드, **복수 선택 1~3개**. `POST /api/onboarding/complete`의 `hobbyId`를 `hobbyIds: string[]`(1~3)로 확장, `h_user_hobbies` 다건 insert
5. **사진 (신규)**: 원형 아바타 placeholder + 카메라 뱃지 버튼 → 파일 선택(웹이므로 시안의 OS 권한 모달은 해당 없음) → 클라이언트 리사이즈(최대 1024px, JPEG) → `h-avatars/{userId}/avatar-{ts}.jpg` 업로드 → `profiles.avatarUrl` 갱신. "건너뛰기" 허용, 완료 → `/welcome`

## 9. 보안 고려사항

- 아이디 찾기: rate limit + 단일 오류 메시지 + 이메일 마스킹 (계정 열거/개인정보 노출 방지)
- 휴대폰: 서버 저장 시 숫자만 정규화, 공개 API 응답에 절대 미포함 (h_meeting_rsvps.guest_phone과 동일 원칙)
- service role 사용은 `/api/auth/find-id` 서버 라우트 내부로 한정
- 스토리지: 본인 prefix에만 쓰기 허용, mime/용량 제한
- 약관 동의: 버전 문자열 포함 저장 (추후 재동의 요구 대비)

## 10. 시안 대비 의도적 편차

| 편차 | 사유 |
|---|---|
| 회원가입에 이름/휴대폰 필드 추가 | 아이디 찾기 동작 전제 (사용자 승인) |
| 비밀번호 찾기: 임시 비밀번호 → 재설정 링크, 이름 필드 제거 | 인프라·보안 (사용자 승인) |
| 필터 모달에서 반경 섹션 제외 | 좌표 데이터 공백 (사용자 승인) |
| 홈 알림 종 미노출 | 알림 페이지 부재, 무동작 UI 금지 원칙 |
| 바텀내비 "정보" 탭 유지 (시안은 "일정") | 사용자 결정, 추후 재논의 |
| 온보딩 음성 가이드 유지, 사진 권한 OS 모달 없음 | 기존 기능 보존 / 웹 플랫폼 특성 |
| 회원가입 닉네임 필드 제거 | 온보딩 닉네임 단계와 중복, 시안에도 없음 |

## 11. 검증 전략

- Phase마다: `npx tsc --noEmit`, `bun run lint` (포맷은 변경 파일 스코프로 — autocrlf 유령 churn 회피)
- 수동 플로우 체크리스트: 가입→온보딩→홈→클럽 필터→모임 히어로, 아이디/비번 찾기 왕복, 카카오 가입자 분기
- 마이그레이션: 로컬/프리뷰 DB에 선적용 후 기존 데이터(클럽 목록, 추천, 공유 라우트) 회귀 확인
- 신규 API는 Zod 경계 검증 + 401/429/유효성 오류 응답 확인

## 12. 오픈 이슈 (사용자/운영 입력 필요)

1. `/login` 히어로 이미지 에셋 — 시안 유사 이미지 제공 필요. 미제공 시 기존 브랜드 일러스트/그라디언트로 대체
2. `/terms`, `/privacy` 본문 — 표준 초안으로 시작, 운영(법무) 검토 필요

4. 기존 가입자 name/phone 공백 — 아이디 찾기 불가 안내 문구로 대응, 프로필 수정에서 입력 유도할지 후속 결정
5. 후속 과제 백로그: 일정 탭, 반경 필터, 알림 페이지, 설정 내 글자 크기 재조정
