# 8월 첫 모임 역산 로드맵 설계 (2026 Q3)

- 작성일: 2026-07-11
- 상태: 사용자 승인된 설계 (구현 계획 작성 전)

---

## 1. 배경

카톡 공유 웨지(2026-07-11 main 머지, 프로덕션 배포·E2E 검증 완료)로 공개 초대장 + 게스트 RSVP까지 동작한다. 다음 단계에 대해 사용자와 확인된 방향:

- **3개월 목표**: 실제 시니어 첫 사용자 확보 + 제품 완성도(목업 제거) + 사업성 검증 — 셋 다 중요
- **유입 경로**: 운영자 주도 모임 + 지인/지역 커뮤니티 시드
- **첫 실모임 시점**: 약 1개월 후 (2026년 8월)
- **수익모델**: 미정 — 참여 지표 먼저 측정, 이후 모임 참가비 실험

접근 방식 3안(모임 루프 역산 / 제품 완성도 우선 / 최소 개발 수동 운영) 중 **모임 루프 역산**을 채택했다. 8월 첫 모임을 고정점으로 두고, 코어 루프에 걸리는 목업만 4주간 제거한다. 루프 밖 기능은 실사용 지표가 요구할 때 만든다.

## 2. 목표와 성공 기준

**고정점**: 8월 중 운영자 주도 첫 모임 1회 이상 실행.

3개월 목표의 정렬: 8월에 실사용자가 코어 루프를 완주하고(사용자 확보), 그 루프에 걸리는 목업만 제거하며(완성도), 9월부터 참여 지표를 읽고 10월에 참가비를 실험한다(사업성 검증).

성공 기준은 "측정 가능해지는 것" 자체다:

- 공유 클릭 → 초대장 뷰 → RSVP 전환율
- RSVP → 회원 가입 전환율
- 재참석률 (2회차 모임 기준)

목표 수치는 첫 데이터를 본 뒤 정한다. 근거 없는 수치를 미리 정하지 않는다.

## 3. 코어 루프 (이번 분기의 유일한 우선순위 기준)

```
운영자: 클럽·모임 개설 → 카톡 초대장 공유
게스트: 초대장 열람 → RSVP (비로그인) → 모임 참석
전환:   가입 CTA → 회원 가입 → 클럽 가입
재방문: D-1 리마인드 → 재참석
```

2026-07-11 기준 루프에서 끊긴 곳 4개 (이번 4주 작업의 전부):

1. **클럽 가입** — `POST /api/clubs/[id]/join`이 TODO 스텁 (가짜 성공 응답)
2. **D-1 리마인드** — `/api/notifications`가 in-memory 배열, `lib/notifications.ts`의 발송이 console.log. `h_push_subscriptions` 테이블은 스키마에 존재하나 미사용
3. **가입 CTA → 클럽 자동 연결** — 게스트가 RSVP 후 회원이 되는 경로 없음
4. **계측** — analytics 도구 전무 (Vercel Analytics, PostHog 등 아무것도 없음)

## 4. 주차별 범위

### W1 (7/14~) — 운영 기반 + 클럽 가입 실연동

- Vercel Git 자동배포 복원 (대시보드에서 repo 연결 — CLI 재생성 프로젝트라 끊겨 있음) + 로컬 main 2커밋 origin push로 동기화
- Kakao OAuth 셋업 확인/완료 — Supabase Kakao provider 활성화 + Kakao Developers redirect URL 등록 (콘솔 작업). 시니어 가입 마찰의 최대 변수라 1주차 배치. 막히면 일반 가입이 폴백
- VAPID 키 생성·Vercel 등록 (W2 선행 조건)
- `POST/DELETE /api/clubs/[id]/join` 실DB 연동 — `h_club_members` INSERT/DELETE, 표준 API 패턴(auth + Zod + api-response + Drizzle) 준수
- 클럽 상세 페이지 가입 버튼 wire + `memberCount` 라이브 계산 (현재 고정값)
- 게스트 RSVP 전화번호 중복 방지 — 웨지에서 "수용된 제약"이었으나 8월 실모임에서 정원을 잘못 채울 수 있어 승격

### W2 (7/21~) — 알림 실체화 (재참석 장치)

- `/api/notifications` → `h_push_subscriptions` DB 저장 (auth 필수, in-memory 제거, anonymous userId 제거)
- `lib/notifications.ts` — `web-push` 라이브러리로 실발송
- D-1 리마인드 Vercel Cron — `vercel.json` crons, KST 09:00 = UTC 00:00 주의
- mypage 알림 설정 토글 DB 연동
- admin D-1 참석자 리스트 — 웹푸시 미수신 시니어(iOS PWA 미설치 등) 대비, 운영자가 카톡으로 수동 발송할 수 있는 보험. 시니어 온보딩 때 후속으로 정의된 항목

### W3 (7/28~) — 게스트 전환 + 참여 계측

- RSVP 완료 화면·초대장에 가입 CTA → 초대 링크 경유 가입 완료 시 해당 클럽에 자동 가입시키고, 완료 화면에 "○○ 클럽에 가입되었습니다"를 명시 (시니어 대상이라 단계 최소화를 우선)
- 최소 이벤트 계측: `h_events` 테이블 (event_name, ref_id, session/user 식별자, created_at) + 서버사이드 기록. 외부 SaaS를 쓰지 않는 이유: 측정 대상이 4~5개 이벤트뿐이고, 시니어 개인정보를 외부로 보내지 않기 위함
- (선택) 모임 좌표 입력 UI — 초대장 "길찾기" 정확도 개선. 운영자 필요 시에만

### W4 (8/4~) — 드라이런 + 안정화

- 운영자 리허설: 실 클럽 생성 → 가족/지인 카톡 공유 → RSVP → 가입 → D-1 알림 수신까지 프로덕션에서 E2E
- 발견 버그 픽스, 시니어 UX 점검 (폰트 스케일·터치 타깃)
- 운영 체크리스트 문서화 (모임 개설부터 당일 운영까지 절차)
- **8월 2주차: 첫 실모임**

## 5. 9~10월 — 운영하며 검증

- **9월**: 주 1회 이상 모임 운영 + 주간 지표 리뷰. 다음 실연동 대상은 지표와 사용자 요구가 결정한다 — 사진 요구가 나오면 파일 업로드, 소통 요구가 나오면 커뮤니티·채팅 순. 참여자가 늘면 정원 카운트 TOCTOU 원자화(count-then-write 3곳)
- **10월**: Toss **단건 결제**로 유료 모임 1회 실험 — 참가비 모델 검증. 구독은 이번 분기 범위 밖

## 6. 선제적으로 만들지 않을 것

실사용 지표나 사용자 요구 없이는 착수하지 않는다:

- 커뮤니티 글쓰기 실연동
- 파일 업로드 (9월에 사진 요구가 확인되면 착수)
- 운세 Gemini DB 저장 (결정적 엔진 폴백으로 충분)
- 구독 결제 (단건 참가비 실험이 먼저)
- 네이티브 앱, 검색 개선, 채팅 검색
